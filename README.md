## التركيب

```bash
# 1) الجداول
mysql -u root -p < db/schema.sql
#    التركيب القديم بيتحدّث بالترقيات بدل كده:
#    mysql -u root -p marking < db/migrate-003.sql

# 2) الإعدادات
cp config.sample.php config.php     # وعدّل بيانات الاتصال

# 3) حساب الـ Main TA (بيعمل كمان 12 لاب بروبريك افتراضي)
php db/install.php main "م. عبدالله" "كلمة-سر-قوية"   # 8 حروف على الأقل
```

بعدها ادخل بحساب الـ Main TA وافتح **استيراد** من اللوحة، ورتّب كده:

1. **المعيدين** — `username,name,password`
   سيب `password` فاضي وهيتولّد واحدة ويعرضهالك **مرة واحدة**.
2. **السكاشن** — `id,name,day,time,room,tas`
   عمود `tas` أسماء مستخدمين المعيدين مفصولة بـ `|` — **الترتيب مهم**، التقسيم بيتبعه.
3. **الطلاب** — `id,name,email,section_id`
   ترتيب السطور في الملف = ترتيب الطلاب جوه السكشن، والتقسيم بيتبعه.

أخيرًا: **الترم → جدول اللابات** وحط تاريخ Lab 1.

## الرفع على استضافة

- ارفع المجلد كله ما عدا `db/seed.php`.
- اعمل `config.php` على السيرفر وحط فيه `'debug' => false`.
- لو الموقع على https: `'secure_cookies' => true`.
- ملفات `.htaccess` موجودة وبتمنع الوصول لـ `config.php` ومجلد `db/`، وكمان
  بتبعت هيدرات الأمان (CSP و `X-Frame-Options` و `nosniff` و `Referrer-Policy`).
  نفس الهيدرات بيبعتها الـ API من `api/_bootstrap.php`، فالـ endpoints محمية
  حتى لو `mod_headers` مش متسطّب.
  لو السيرفر **nginx**، إعدادات `.htaccess` مش هتشتغل — لازم تنقل المنع
  والهيدرات للـ server block.
- لو الموقع كله https، فعّل سطر `Strict-Transport-Security` المعلّق في `.htaccess`.
- غيّر كلمات سر كل الحسابات التجريبية.

## اللابات: الجدول الأسبوعي

اللاب بيفتح ويقفل لوحده:

```
نافذة اللاب N = startDate + (N-1)×7 يوم، لمدة weekDays
```

التواريخ بتتحسب UTC. التجاوز اليدوي من اللوحة بيغلب الجدول،
و«رجّع للجدول» بيمسح التجاوز (`state_override = NULL`).

## تقسيم الطلاب

`section_assignment()` في `api/_bootstrap.php` بتقسّم طلاب السكشن على معيدينه
**بلوكات متتالية**، والبلوكات **بتلف كل لاب** عشان الطالب ميجيش لنفس المعيد كل أسبوع.

التقسيم **محسوب مش متخزّن** — يعني لو غيّرت معيدين السكشن بيتظبط لوحده.
جدول `lab_assignments` للتجاوزات بس (نقل طلاب معيد غايب).

## الطابور المحلي (الأوفلاين)

`assets/js/api.js` بيتأكد من الشبكة قبل أي كتابة. لو النت مقطوع:
الدرجة بتظهر للمعيد على طول، والعملية بتدخل طابور في `localStorage`،
وبتتبعت لوحدها على حدث `online`.

الإعادة آمنة لأن `marks` عليها `UNIQUE (student_id, lab_id)` والحفظ
`INSERT … ON DUPLICATE KEY UPDATE`.

القراءات كمان بتتخزن نسخة محلية، فالصفحات بتفضل تفتح من غير نت.

### مفيش درجة بتضيع في صمت

كل عملية في الطابور ليها 3 مصاير بس:

| | |
|---|---|
| **اتقبلت** | خلاص |
| **الشبكة لسه مقطوعة** | بتفضل في الطابور وبتتحاول تاني |
| **السيرفر رفضها** | بتروح لقايمة «محتاجة مراجعة» وبتظهر للمعيد في `sections.html` |

كل حفظ بيحمل `at` — وقت التصحيح الفعلي. لو اللاب اتقفل والمعيد لسه مقطوع،
السيرفر **بيقبل الإدخال** لأنه اتعمل واللاب كان مفتوح، وبيسجله في سجل التعديلات
بسبب واضح. التاريخ اللي برّه نافذة اللاب أو في المستقبل بيترفض.

> الجلسة بتفضل `session_hours` ساعة (10 افتراضيًا). الافتراضي في PHP 24 دقيقة —
> وده كان بيطرد المعيد وهو بيصحّح.

## اللغة — عربي وإنجليزي

الواجهة كلها بالعربي الفصيح والإنجليزي، والتبديل من الزرار اللي فوق على اليمين
في كل صفحة.

- `assets/js/i18n.js` فيه القاموس كله. الصفحات مفيهاش نص ثابت — كل حاجة
  `data-i18n="key"` أو `t('key')`.
- الاختيار بيتخزن في `localStorage` وكمان في كوكي `marking_lang`، عشان الـ PHP
  يقراه. يعني `tools/import.php` بيترسم من السيرفر باللغة الصح، ورسايل الأخطاء
  اللي جاية من `api/` بتوصل بنفس لغة الواجهة.
- الاتجاه (`rtl` / `ltr`) بيتظبط على `<html>` قبل أول رسم، فمفيش رفرفة.
  الـ CSS كله بيستخدم `inline-start` / `inline-end`، فمفيش حاجة محتاجة تتقلب بالإيد.
- `users.lang` بيتسجل لوحده كل مرة الشخص يدخل، والتنبيهات بالإيميل بتتبعتله
  باللغة اللي هو شغال بيها.

> لو ضفت نص جديد، ضيف مفتاحه في `assets/js/i18n.js` (للواجهة) أو
> `api/_lang.php` (لرسايل السيرفر) — باللغتين.

## سجل الإجراءات الإدارية

تغييرات الدرجات ليها سجلها في `marks.reason`. أي حاجة تانية الـ Main TA بيعملها
بتتسجل في جدول `audit_log` وبتظهر في **اللوحة → السجلات**:

فتح وقفل اللابات · تعديل الروبريك · تعديل الجدول · نقل الطلاب ·
البتّ في الطلبات · إضافة وتعديل وإيقاف الحسابات · إعادة كلمات السر ·
تعديل سكاشن المعيد · الاستيراد.

كل سطر فيه مين عمل الإجراء وإمتى ومن أنهي IP. اسم الشخص بيتخزن مع السطر
(مش بس الـ id) عشان السجل يفضل مقروء حتى لو الحساب اتشال.

## تنبيهات الإيميل

الرسايل **مش بتتبعت من جوه الطلب** — بتتحط في جدول `mail_queue`
و `tools/cron.php` هو اللي بيبعتها. كده الحفظ مبيستناش السيرفر البعيد،
ولو الإرسال فشل بيعيد المحاولة (5 مرات قبل ما يعتبرها `failed`).

بتتبعت في حالتين:

| الحدث | بيروح لمين |
|---|---|
| معيد بعت طلب تعديل | كل الـ Main TA |
| الـ Main TA وافق أو رفض | المعيد صاحب الطلب (مع سبب الرفض) |

الإعداد في `config.php` تحت `'mail'`. طريقتين:

- **`smtp`** (مستحسن) — عميل SMTP مكتوب بالإيد، بيدعم STARTTLS (587) و SSL (465) و AUTH LOGIN.
- **`mail`** — دالة PHP العادية. أسهل بس بتروح spam كتير.

إيميلات المعيدين بتترفع من `tools/import.php` (عمود `email`).
`users.notify = 0` بتوقف التنبيهات لشخص معيّن.

## المهام الدورية

```bash
php tools/cron.php
```

بتعمل حاجتين: تبعت طابور الإيميلات، وتاخد نسخة احتياطية.

حطها في cron بتاع الاستضافة كل 5 دقايق:

```
*/5 * * * * php /home/user/public_html/marking/tools/cron.php >/dev/null 2>&1
```

لو الاستضافة مفيهاش CLI cron، حط `token` في `config.php` واستخدم:
`https://.../tools/cron.php?token=...`

### النسخ الاحتياطي

مكتوب بـ PHP من غير `mysqldump` (مش متاح على أغلب الاستضافات المشتركة).
بيطلع `.sql.gz` في `db/backups/`، مرة كل `every_hours`، وبيحتفظ بآخر `keep` نسخة.

الاسترجاع:

```bash
gunzip -c db/backups/marking-20260921-193143.sql.gz | mysql -u root -p marking
```

> مجلد `db/` محمي بـ `.htaccess`. لو على nginx، امنعه في الـ server block.

## تعديل الروبريك

من اللوحة: **الترم → روبريك اللاب**. تقدر تغيّر النص والنقط وتضيف وتحذف بنود.

مجموع النقط هو درجة اللاب. لو غيّرت النقط والدرجات متسجلة بالفعل،
سيب **«أعد حساب الدرجات المسجلة»** شغالة — السيرفر بيعيد حساب كل درجة
من البنود اللي المعيد علّم عليها، وبيرجّعلك عدد اللي اتغير.

الدرجات اليدوية (اللي المعيد دخّلها من غير روبريك) والغياب **مش بيتأثروا**.

> أكواد البنود (`r1`, `r2`, …) بتتحفظ لما تعدّل النص — عشان الدرجات المسجلة
> تفضل مربوطة بالبند الصح. البند الجديد بياخد كود فاضي والسيرفر بيولّدله واحد.

## إدارة المستخدمين

**اللوحة → المستخدمين** (`users.html`). للـ Main TA بس.

- إضافة معيد — سيب كلمة السر فاضية وهتتولّد وتظهرلك **مرة واحدة**
- تعديل الاسم والإيميل والدور وتشغيل/إيقاف تنبيهات الإيميل
- **كلمة سر جديدة** — القديمة بتبطّل فورًا
- **السكاشن** — تحديد السكاشن اللي المعيد مسؤول عنها، والتقسيم بيتحسب منها
- **إيقاف** بدل الحذف — الحساب بيتقفل ودرجاته بتفضل مربوطة باسمه

حمايات مفروضة في السيرفر:

| | |
|---|---|
| مش هتقدر توقف حسابك إنت | `users.php` |
| مش هتقدر تنزّل نفسك من Main TA | `users.php` |
| لازم يفضل Main TA واحد شغال على الأقل | `users.php` |
| الصفحة والـ endpoints كلها للـ Main TA بس | `require_main()` |

## سجل الدخول

كل محاولة دخول بتتسجل في `login_log`: **ناجحة وفاشلة**، بالوقت والـ IP ونوع الجهاز.
بيظهر في آخر `users.html`، وفيه فلتر **«المحاولات الفاشلة»** — لو شوفت محاولات كتير
على حساب واحد، ده مؤشر إن حد بيحاول يخمّن.

بيتسجل كمان `users.last_login` عشان تشوف مين مدخلش من زمان.

### الفرملة

الفرملة بتتحسب من `login_log` نفسه مش من الجلسة، يعني مسح الكوكيز أو جلسة
جديدة مش بيصفّروها:

| الحد | القيمة |
|---|---|
| نفس الحساب من نفس الـ IP | 8 محاولات فاشلة / 15 دقيقة |
| نفس الـ IP على أي حساب | 40 محاولة فاشلة / 15 دقيقة |

حد الـ IP عالي عن قصد لأن المعيدين في اللاب بيطلعوا كلهم من نفس الـ NAT،
وحد الحساب هو اللي بيعمل الشغل الحقيقي.

## لسه محتاج شغل

- **تصدير سجل الإجراءات** — بيتعرض في اللوحة بس، لسه مفيش CSV ليه.
